# 三要素切分器（纯规则，无模型）

把裁判文书摘要切成三个要素区间：`plaintiff_claims`（原告诉讼请求）、
`defendant_defenses`（被告辩称，可缺失）、`court_facts`（法院认定事实及说理）。
实现只依赖标准库，不用任何模型。代码在 `src/sfzy/segment/`：

| 文件 | 职责 |
| --- | --- |
| `patterns.py` | 全部正则与词表（强/中/弱三档），改规则只改这里 |
| `segmenter.py` | 句子切分、标志扫描（含动词锚定的弱答辩标志）、顺序校验、区间装配、状态与置信度 |
| `cache.py` | 离线缓存（人工摘要预热）与实时切分两条链路 |
| `tools/segment_report.py` | 在真实数据上跑统计 + 导样例 |

## 1. 一句话设计

**强特征优先 → 顺序校验 → 弱特征补充**，边界一律是**字符偏移量**（不按句子切），
要素状态区分「识别 / 确认缺失 / 不确定」三种，后者绝不偷偷降级成前者。

## 2. 切分流程

```
文本
 ├─ 句子切分（。！？!? 为硬句界；；; 为软句界，只在推断时用）
 ├─ 标志扫描
 │    P: 原告诉请 / 原告请求 / 请求判令 …（STRONG/MEDIUM）
 │    D: 被告辩称 …（STRONG）＋ 动词锚定的弱扫描（未答辩声明 / 陈述动作词 / 具名 / 并列 / 角色 / 光名）
 │    F: 经审理查明 / 本院查明 / 法院查明 / 经查 / 经审查 / 经审理 …（STRONG/MEDIUM/WEAK）
 │    尾部: 依照《…》…判决 / 判决如下 / 书名号+规定+判决 / 法律依据从句 / 兜底 5 档
 ├─ ① 诉请起点：第一句有标志 → 标志处；否则跳过"案件背景"句，从第二句开始
 ├─ ② 答辩起点：第一个答辩标志，过三道顺序校验（见下）
 ├─ ③ 答辩终点：优先法院叙述标志；否则句边界+法院语气打分推断；再不行 → 不确定
 ├─ ④ 法院事实起点：继承答辩终点（无答辩则继承诉请终点）
 └─ ⑤ 法院事实终点：尾部标志起点（找不到 → 文末并记不确定）
```

### 需求①②③对应的几个关键点

**①「默认第二句」与「案件背景」怎么判**：先看第一句有没有诉请标志（有就从标志处开始）。
否则把句尾的案由短语（`……纠纷 / 一案 / 关系`）剥掉再找诉请动词——
`原被告系借款合同纠纷。` 剥完是空 → 判为背景并跳过；
`原被告继承纠纷一案，告诉请依法继承房屋份额。` 剥完还剩"告诉请继承……" → 判为诉请、
不跳。只剥离案由、不看动词表，是因为案由里的"继承""赔偿"和诉请里的动词是同一个词。

**②答辩的三个"不能"**：

* *不能仅凭"被告"起段*：`被告` 必须跟答辩动词（词表里"被告+主张"单独一档、强度降级）；
* *不能把说理里的"被告辩称"当新段落*：第一个法院叙述标志若出现在答辩标志之前，
  该标志按"说理回述"否掉并记 note，答辩判为**缺失**（不是不确定）；
* *不能默认答辩只占一句*：没有法院叙述标志时，从答辩起点所在句**下一句**开始逐句
  打分（强说理语素 +2、弱说理语素≥3 个 +2、当事人主张用语 −2），够 2 分才认作法院事实起点；
  一句都够不上就把答辩与法院事实**一起**记不确定。

### 答辩标志的完整清单

起点 = 全文第一个答辩标志。标志来自两套扫描：先是正则（`D_MARKER_RULES`），
再是**动词锚定**扫描（`_weak_defense_hits`：线性扫答辩动词，再往前回看 ≤22 字判主语）。

| 触发形态 | 规则名 | 档 |
| --- | --- | --- |
| `(原审)?(两/三/…/各/众?被告｜被上诉人｜被申请人｜被反诉人) …(答辩意见｜答辩｜辩称｜抗辩)(?!的)` | 被告+答辩动词 | strong |
| `…被告…(主张｜辩称意见)` | 被告+主张 | medium |
| `…被告…辨称`（"辨"混"辩"的错别字） | 错别字辨称 | weak |
| 主语（被告/具名/角色词）＋ `未｜没有｜无｜不` ＋ 穷举动作词（`出庭/到庭/应诉/缺席/予以/作出/作/进行/做/发表/提出/出具/提交/提供/予/书面/邮寄/口头/正式/公开/答辩期/举证/辩论`）＋ `答辩｜抗辩` | 未答辩声明 | medium |
| 主语（被告/当事人名）＋ `承认｜表示｜不同意｜不认可｜不予认可｜有异议｜无异议｜反驳｜否认` | 陈述动作词 | weak |
| 企业/机构后缀主语（`公司/银行/支行/合作社/村委会/居委会/医院/学校/中心/事务所/工厂/厂/店/管理局/委员会`…） | 具名当事人辩称 | weak |
| 角色词主语（`被告/保证人/担保人/第三人/反诉被告/上诉人/被上诉人/被申请人`） | 角色主体辩称 | weak |
| 主语含顿号/与/及（并列主体责任） | 并列主体共同辩称 | weak |
| 2–4 字光名字主语 | 光名主体辩称 | weak |
| `缺席/未到庭/未出庭/未应诉` | 只有和角色词同现才算"未答辩声明" | medium |
| 主语含 `本院/法院/原告/证人/检察院/人民法院`，或动词后紧跟"的" | 直接弃掉 | — |

上下两条容易切错的地方，都写进了单元测试：

* **数量词前缀属于主语**：`四被告均未作答辩` 必须整段切出来，不能切成
  `…连带清偿责任。四|被告均未作答辩。`（实测修掉 249 条；`D_QUANTIFIER_PREFIX`）；
* **切片两端不留悬挂标点**：边界若落在从句分隔符上，收掉末尾的 `，、：`——
  下一个要素的起点本来就从句中开始，那个逗号不属于前一段。

两条踩过坑的细节：

* **否定词后面的动作词是穷举的**，不是"任意若干字"——否则"被告未提供证据证明其抗辩
  理由成立"这类法院说理会变成"被告未答辩"；
* **"陈述动作词"的主语必须真的像当事人**：`D_ACT_VERB_SUBJECT_BLOCK` 挡掉
  `意思/真实/明确/书面/双方/各方/当事人/内容/行为/事实/约定/协议/合同`。
  实测最大的误检是"双方当事人真实**意思表示**"（主语被回看成"真实意思"）：
  加主语校验前 273 条命中，加完 61 条，留下的基本是"被告承认原告的诉讼请求""被告无异议"。

**③尾部识别**：候选只在全文尾部区域找；按强度取档（强档有就绝不用弱档）；
同档里取最靠右的一个（尾部一定是最后一段，这样能躲开说理里"依据《…》之规定，
……驳回……"的伪尾部）；同句内再往前扩到"纯法律依据从句"的开头，并做两条硬约束：

* **引用串到裁判结果动词之间不许夹说理词**（"原告/被告/辩称/诉讼请求/予以支持"等），
  否则这个"驳回"是说理里的；
* 往前扩不超过 80 字，且只在"从句开头"的引导词处扩——既不会把"无法律依据"的
  "依据"当起点，也不会在整段没有句号的摘要里把法院事实整段吞掉。

`依据证据认定事实`、`依照合同约定` 这类日常"根据/依照"都不满足"真引用法律"
（必须有书名号 / 第X条 / 之规定 / 依照+法律·法规·规定），因此不会被当成尾部。

## 3. 三种状态，别混

| 状态 | 含义 | 谁会出现 |
| --- | --- | --- |
| `identified` | 起止都锚上了 | 三个要素 |
| `absent` | **确认缺失**（全文没有任何答辩标志，或标志被顺序校验否掉） | 只有被告辩称 |
| `uncertain` | **规则无法确定边界**（有迹象但定不下来） | 三个要素 |

另外每条区间都记了 `start_rule` / `end_rule`（"这一刀是谁下的"）、
`confidence`（high/medium/low，取两个边界里更弱的一个）和 `notes`
（例如"答辩标志出现在法院叙述标志之后，按说理回述处理"）。

两条容易忽略的一致性：

* **没有答辩时，诉请终点与法院事实起点是同一条边界**——这条边界定不下来时，
  诉请也一起记不确定，不会只报一边；
* **答辩终点定不下来时**，答辩与法院事实都记不确定（不把答辩终点硬塞到尾部起点上）。

## 4. 实测（`data/splits/train.jsonl` 的 `summary` 字段，10,738 条）

命令：

```bash

    --data data/splits/train.jsonl \
    --out outputs/segment_report \
    --cache-out data/segment_cache/train_summary_segments.jsonl \
    --segments-out data/segment_cache/train_summary_segments.detail.jsonl
```

| 指标 | 数值 |
| --- | --- |
| 原告诉请 识别 / 缺失 / 不确定 | 99.2% / — / 0.8% |
| 被告辩称 识别 / 缺失 / 不确定 | 77.0% / 20.9% / 2.1% |
| 法院事实 识别 / 缺失 / 不确定 | 97.0% / — / 3.1% |
| **完整切分率** | **96.9%** |
| **不确定边界比例** | **3.1%** |
| 顺序合法率（P→D→F 且不重叠） | 100%（10,738/10,738） |
| 实时切分速度 | ~1,300–1,600 条/秒（单进程，纯 CPU） |
| 离线缓存 | 11 MB（只存区间与来源，不存正文）；查表 ~15 万条/秒 |

切片收尾（"是不是以句末标点结束"）：原告诉请 **95.6%**、被告辩称 **98.5%**、
法院事实 **93.3%**。剩下的都是**字符级切分的固有结果**——下一个要素的标志本来就在
句子中间，例如 `…被告没有能力补偿，依照《继承法》…判决…`（尾部从句子中间起）或
`…享有优先受偿权，被告未答辩。`（答辩从句子中间起）。要"只切整句"就只能放弃
同句多要素这种样本，见需求③的字符级要求，所以保持现状（只收掉悬挂的从句标点）。

答辩终点的来源分布（说明"强特征优先"确实在起作用）：法院叙述标志 6,50x 条、
未答辩声明的句边界 ~41x 条、法院归纳的"争议焦点"弱标志 ~31x 条、
没有任何标志时的句边界推断 ~96x 条、推断失败（记不确定）227 条。
答辩起点的来源分布：被告+答辩动词 5,088、未答辩声明 2,806、陈述动作词 61、
具名/并列/角色/光名 480、被告+主张 54、错别字 9，其余 2,240 条确认无答辩段落。
法院事实终点的尾部标志命中 10,699 条（99.6%），剩下 39 条取文末并记不确定。

要点解读：

* **诉请的 0.9% 不确定全部来自"法院事实起点定不下来"**（两者共用一条边界），
  不是诉请起点没找到；
* 被告辩称的 21.7%"确认缺失"是结构性的（摘要里本来就没有答辩段，或答辩只作为
  法院说理的转述出现）；
* 剩下 3.1% 的不确定集中在两处：答辩终点无法推断（约 2%）、
  法院事实终点找不到尾部标志（约 0.4%），报告里逐条列了成因与样例。
* 在 GRPO 采样输出上（`data/triples/grpo_val_v48.jsonl` 的 `output`，1,340 条）
  完整切分率 99.1%、不确定 0.9%，不需要为模型输出单独加规则。

自洽性检查（不需要人工标注，报告第 4 节）：答辩片段内无答辩词 63 条、
法院事实片段内无说理语素 150 条、尾部内无裁判结果标志 107 条、诉请片段内无诉请动词 4 条。
这些是"可能切歪"的候选，报告都配了样例，人工扫一遍即可判断是规则问题还是摘要本身就这样写。

报告与样例在 `outputs/segment_report/report.md`（含每个规则桶的典型样例、
自洽性检查：答辩片段里有没有答辩词、法院事实里有没有说理语素、诉请里有没有诉请动词）。

## 5. 两条使用链路

## 5.5 附："字面 `。被告`"这条直觉，实测站得住

判据是**字面**两个字符"句号 + 被告"，不是"任意句子里以被告开头"。两者差别很大：
前者在 train 集上与现有规则一致 **96.6%**（10,375/10,738），只在这三类上分歧：

| 情形 | 条数 | 谁对 |
| --- | --- | --- |
| 字面规则更早 | 57 | **字面规则对**（"被告吕雪松同意还款""被告胡萍称欠款属实"这类没有"辩"字的答辩陈述，原规则漏了） |
| 字面规则更晚 | 151 | 原规则对（前面已经有具名被告答辩，如"被告胡建波未作答辩。被告山东顺发…辩称"） |
| 一侧判缺失 | 155 | 加语气护栏后只有 16 条可用——多数"句首被告"句是以被告为主语的法院说理 |

注意第 2 行这个例子：原文是 `…经济损失，被告胡建波未作答辩。被告山东顺发建筑安装
有限公司辩称…`——**逗号**在"被告胡建波"前面，所以字面 `。被告` 落在第二个被告身上；
而现有规则（"未答辩"声明）正好落在"被告胡建波未作答辩"上。反过来，诉请列表里的
`…；被告偿还原告借款本金及利息；…` 前面是**分号**，也匹配不上字面 `。被告`——
这正是这条判据能躲开诉请条目的原因。

落地方式：

* **默认兜底**（`bare_defendant_backstop=True`）：所有答辩标志都落空时，才用
  "字面 `。被告` + 8 字内紧跟答辩动作词 + 不是判决条目 + 无法院语气"取起点。
  实测命中 16 条（0.15%），抽查全是真答辩段落（`被告长大公司称…`、`被告反诉称…`、
  `被告王才军对借款事实无异议`、`被告高某未在法定答辩期内提交答辩`）。
  来源记成 `被告辩称:句首被告兜底`，可在报告里单独统计。
* **可选覆盖**（`--d-bare-first` / `Segmenter(prefer_bare_defendant=True)`）：
  按字面规则**直接**取第一个 `。被告` 当起点，供做 A/B 对照。它会按上表把 151 条
  切到第二个被告身上、把 57 条提前到更早的答辩句（后者是赚的），全量完整切分率
  96.9% → 96.2%。

顺便说一句：数据里还有 ASCII 句点写的 `.被告`（实现里按"。"和"."都算句末）。

```python
from sfzy.segment import Segmenter, SegmentCache

# 实时：GRPO 候选摘要（每次采样都是新文本，没法预热）
res = Segmenter().segment(candidate_text)
res.text_of("plaintiff_claims")
res.spans["defendant_defenses"].status  # identified / absent / uncertain

# 离线：人工摘要（训练前固定，反复切）
cache = SegmentCache.load("data/segment_cache/train_summary_segments.jsonl", writable=False)
cache.get_or_segment(reference_text)   # 命中查表；未命中现算，**不落盘**
```

缓存键是正文 sha1，值里带 `n_chars` 与完整偏移量；`writable=False` 时
`get_or_segment` 只读不写——rollout 里的随机文本不会污染缓存。

## 6. 边界（本次刻意没做的事）

* **没有接入 reward，也没有改 GRPO 训练逻辑**：本模块只提供切分结果与统计；
* 没有做要素级语义匹配（那是 fact coverage / judge 的事）；
* 跨句的"争议焦点"归纳、倒装（先结论后事实）等结构，目前靠弱标志与推断兜，
  这类样本会以 `low` 置信度或 `uncertain` 出现在报告里，而不是被硬切。
